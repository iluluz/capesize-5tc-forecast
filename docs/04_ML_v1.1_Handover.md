# ML → DL hand-over: `ml-v1.1`

**Status:** tagged `ml-v1.1` (2026-11-10). It replaces `ml-v1.0` as the ML input to the text branch once the DL
owner confirms (see the decisions log). `ml-v1.0` stays available, so nothing breaks in the meantime.

## TL;DR for the text branch

- **Same file, same columns, same rows.** Only the numbers and `model_version` change.
- In the Hormuz window (2025-09 → 2026-08), the v1.1 residuals have a correlation of 0.99 with the v1.0 residuals,
  so your results should barely move.
- v1.1 is better overall at h = 5 and has a calibrated 80% band.
- To switch: re-run your pipeline on the new file and filter on `model_version == "ml-v1.1"`.

## Files (shared drive → `data/processed/`, not in Git)

| File | Content |
|---|---|
| `ml_oos_predictions.parquet` | **v1.1**: `model_version = "ml-v1.1"`. Use this one. |
| `ml_oos_predictions_v1.0.parquet` | The previous version, unchanged, for comparison or rollback. |
| `baltic_5tc_trading_days.csv` | The 5TC trading-day calendar, unchanged. |

**Schema** (unchanged, C7): `date, h, y_true, yhat, q10, q50, q90, model_version, train_end`

- One row per (date, h), with h ∈ {5, 20}.
- h = 5: 2019-01-02 → 2026-10-16, 1,948 rows. h = 20: 2019-01-02 → 2026-09-25, 1,933 rows.
- `y_true = ln(S_{t+h} / S_t)` for 5TC. `yhat` is the point forecast made at `date` (13:00 London, FFA lagged one day).
- **Residual for the text branch:** `y_true - yhat`.
- `q10` / `q90`: an 80% band, calibrated by ACI. Coverage is 0.80 at both horizons and 0.75–0.83 in every year.
  `q50` is the median.
- Every row is **out of sample**: walk-forward, monthly refit, purge h + embargo h. `train_end` = the last
  training date, the same as in v1.0.

## What v1.1 is

v1.1 is an equal-weight average of three models, with no fitted weights:

| Member | What it is |
|---|---|
| ridge | the v1.0 linear model |
| VECM | spot + FFA curve, cointegrated (new) |
| `lr_path` | LightGBM on the FFA residual, with path / turning-point features (new features) |

The interval uses `lr_path` quantiles shifted to the average forecast, then adaptive conformal (ACI).
v1.0 was ridge + LightGBM residual, with a CQR interval.

## How good (Theil U vs random walk, lower = better; 2019-01 → 2026-10)

| | h = 5 | h = 20 | 80% coverage h5 / h20 |
|---|---|---|---|
| FFA-implied | 1.127 | 0.849 | – |
| v1.0 | 0.951 | 0.854 | 0.75 / 0.73 (file `q10`–`q90`) |
| **v1.1** | **0.928** | 0.854 | **0.80 / 0.80** |
| Hormuz window 2025-09 → 2026-08, v1.0 | 0.921 | **0.878** | 0.80 / 0.94 |
| Hormuz window 2025-09 → 2026-08, v1.1 | 0.920 | 0.891 | 0.80 / 0.92 |

**Selection:** pre-registered rule (mean U, 2019–22 selects, 2023–26 confirms). v1.1 met all three thresholds
against v1.0:

- 2019–22 mean U 0.909 vs 0.923;
- 2023–26 mean U 0.861 vs 0.866;
- DM test at h = 5: p < 0.001. At h = 20 the two are equal.

## Caveats

- **2026 is slightly worse at h = 20:** v1.1 0.965 vs v1.0 0.944. This year is inside your event window, so if you
  compare text-branch results across versions, report both.
- Do not use h = 40/65 from v1.1. FFA is the best forecast at long horizons, and v1.0 is closer to it.
- **Not used:** Chronos-2 (foundation model). It helped a little, but it was pre-trained on public data that may
  overlap 2019–25, so it could leak.
- Feature-group and method details: `outputs/tables/v11_*.csv` and `experiments/results.csv`, rows with
  `notes` starting with `ml-v1.1`.

## Reproduce

You do not need to re-run the ML; the parquet is enough. If you want to:

1. Check out the tag and install: `git checkout ml-v1.1`, then `pip install -r requirements.txt`.
2. Build the feature store with `evaluation.build_store_v2()`.
3. Run the members: `run_ridge`, `stats_models.run_vecm`, and `run_lgbm(..., residual=True, feats=v1 + pth_*)`.
4. Combine them with `evaluation.average_oos`, then add the interval with `ensemble.aci_interval`.
5. Export with `evaluation.oos_export`.

The `lr_path` run takes about 15 minutes on 8 cores. Questions → ML owner (iluluz).
